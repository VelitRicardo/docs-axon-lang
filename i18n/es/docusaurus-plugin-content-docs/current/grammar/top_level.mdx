Toda primitiva de AXON es o bien **de nivel superior** (se sostiene sola en la
raíz del programa) o bien **anidada** (solo aparece dentro de otra
construcción). El compilador lo impone en tiempo de parseo: una declaración
`step` fuera de todo `flow` es un error de sintaxis; una declaración `flow`
*dentro* de otro `flow`, también.

Esta página es la tabla autoritativa. Cuando un agente dude sobre dónde va una
primitiva, debe consultar este recurso — toda decisión se sigue de una fila.

## Cómo leer esta tabla

- **Superficie** — la palabra clave de AXON tal y como aparece en el código.
- **Nivel superior** — `✓` si la palabra clave abre una declaración de nivel
  superior; `✗` si solo aparece anidada.
- **Vive dentro de** — para las primitivas anidadas, la construcción o
  construcciones que pueden contenerla.
- **Categoría** — la familia a la que pertenece la primitiva (alimenta la
  faceta `axon.primitives(filter)`).
- **Desde** — el ciclo que la introdujo.

## Sentencias (no son primitivas, pero se parsean en el cuerpo de un flow)

Son sentencias que un agente trata como el cuerpo de un `flow`. NUNCA van en el
nivel superior.

| Superficie | Vive dentro de | Qué hace |
|---|---|---|
| `if … else`   | cuerpo de `flow` | Rama condicional |
| `for x in …`  | cuerpo de `flow` | Iteración acotada |
| `let x = …`   | cuerpo de `flow` | Enlace local |
| `return …`    | cuerpo de `flow` | Retorno anticipado o explícito |
| `break`       | dentro de `for` | Salida anticipada del bucle |
| `continue`    | dentro de `for` | Siguiente iteración |
| `run …`       | nivel superior — pero es un *enlace*, no una declaración | Enlaza un flow con persona + context + anchors |
| `apply`       | campo del cuerpo de `step` | Invocar a otro flow |

## Disciplina de composición

- **Los flows componen con `apply`, no anidándose.** Una declaración `flow` no
  puede aparecer dentro de otro `flow`. Los subflows se *referencian* desde el
  cuerpo de un `step` con `apply: <FlowName>`.
- **Los anchors y los shields se enlazan por `run`, no por la cabecera del
  flow.** Un flow no enumera sus restricciones; lo hace la sentencia `run` que lo
  ejecuta, mediante `constrained_by [...]`.
- **Las personas, los contexts y los tools se referencian, no se vuelven a
  declarar.** Un flow que usa una persona la referencia (`as <Persona>` en el
  `run`, o `use <Persona>` en cada step). No incrusta una declaración nueva.

Para el *porqué* de estas reglas, lee `axon://logic/flow_composition`.
